# 2026-10-23

## 결정사항
- **2단계 = B 구조**(사용자 선택): 질문마다 엔진을 띄우지 않는다. 상주 서버 + 에디터 안 실행 + (나중에) 캐시·증분 내보내기.
  - 이유: 엔진을 띄우는 데 매번 십여 초가 듦(사용자가 가장 큰 단점으로 지적). 측정 결과 시간 거의 전부가 엔진 시작(9~13초), 에셋 목록 스캔은 0.26초.
  - 기각: `.uasset` 직접 해석(C안) — 부족할 때 다시 논의(보류).
  - 단계별 시간 로그는 넣음. "스캔 범위 줄이기"는 작업 범위를 줄이는 경우라면 안 된다는 조건이 붙었고, 측정상 스캔이 0.26초라 하지 않음.
- 발표 영상(공개된 사례 발표)은 Claude가 자막 전체와 주요 장면 8개를 직접 확인해 기능 아이디어만 정리 → 2단계 후보 목록(교차 검색, 참조 관계, 리비전 diff, 연결 고리 추적, 설정 최종값 등).
- 테스트 세션 제안 3건 반영: StateTree 같은 이름 경로에 `[n]`, 스키마 컨텍스트는 `Context:Actor`, 커맨드렛 텍스트 언어를 영어로 고정(+자동 배치된 비활성 노드는 `"ghost": true`).
- **핀 id는 연결이 있거나 분할 핀 부모일 때만 쓴다.** 사용자는 그대로 둬도 되는지 물었고, 2단계에서 결과 비교로 변경을 판단하므로 결정적 출력이 필요하다고 설명 → 사용자가 나머지 1단계 작업을 Claude에게 맡김.
- 커밋 메시지에는 Co-Authored-By 줄만(Claude-Session 줄 없음) — 사용자 요청으로 첫 커밋을 amend.
- 2단계 순서 확정(사용자 승인): 2-1 MCP 틀 + AnimBP·StateTree 도구 → 2-2 나이아가라 → 2-3 검색·diff + 캐시. BP 그래프 요약은 뒤로.
- MCP 연결 구조: 우리 도구를 내장 서버에 `AddTool`로 직접 등록(툴셋 3단계 호출을 거치지 않음), 에디터가 꺼져 있으면 우리 커맨드렛이 같은 서버를 띄움 → [[Unreal MCP 내장 서버]].
